# Component lab

`/lab` in `apps/ui-next` renders every reusable component and polished interaction live, on
fixtures, with no daemon. Source: `src/lab/` (route `src/app/lab.tsx`).

- **Open one entry:** `/lab?c=<id>` (ids below). Replay remounts the entry from fresh fixtures;
  the speed control (1×, 0.5×, 0.25×) sets the playback rate of every CSS animation and
  transition on the page and stretches the fixture host's timers.
- **Fixture host:** `src/lab/client.ts` stands in for the daemon client (installed with
  `attachFixtureClient` in `daemon/store.ts`, which the app never calls). It answers session,
  timeline, provider, project, command, account, usage and checkout reads, plays agent turns
  (thinking, a running tool call, a streamed reply), and answers permissions. `src/lab/sim/`
  simulates the rest of the host (table below). A method nobody simulates still rejects with
  "not available in the component lab", so a new RPC shows its error state until it is added.
- **No daemon:** `app/_layout.tsx` skips `connect()` on `/lab`.
- **Static build:** `FROGG_WEB_BASE_URL=/lab` sets Expo's `experiments.baseUrl` so the web
  export can be served from a subpath.

Not simulated, and why:

- Pairing crypto, account export credentials: static fakes; nothing real to sign or decrypt.
- `terminals_changed` pushes: the panel updates locally instead.
- Untracked and ignored markers: the protocol's diff has no untracked/ignored flag, so untracked files show as added and ignored folders (`node_modules`, `dist`) list unmarked, as on a real host.
- Subagent "queued": the protocol has no queued status; the fourth child is canceled.
- `addProject` and account edits mutate the shared fixture arrays and survive a reseed.

## Adding an entry

Add an `Entry` to the matching file in `src/lab/entries/`: `id`, `name`, `category`, `path`,
`purpose`, `usedBy`, `polish` (motion as found in code: property, duration, easing) and
`variants` (each a component with an optional fixed height). `setup` runs after the fixtures
reseed. Follow the app's lint rules (no inline objects or arrows as props).

- Numbers that accompany an animated fill/bar lerp with it (CountUp: `useCountUp` / `<Num>` in
  `components/CountUp.tsx`), on the fill's duration and curve.

## Decisions

An entry awaiting the user's call sets `decision: "<the question>"` on its `Entry`. The lab then
shows an amber DECIDE chip on its index row and overview card, an amber dot + count in its
category header, a "Needs decision" group at the top of the index and overview, and an amber
callout above the polish notes. To clear it once answered, delete the `decision` field (and
apply the pick).

## Findings

Recorded from the audit; nothing here was changed.

### Duplicated or near-duplicate components

- **Two meters.** `Meter.tsx` (20 segmented cells, amber ≥ 70, coral ≥ 90) and
  `settings/pages/kit.tsx` `Meter` (continuous bar, amber ≥ 70, coral ≥ 85). `UsagePanel`'s
  `useToneFor` adds a third threshold source (the device's warning and critical settings).
- **Host banners are toasts now** (`toast/HostToasts.tsx`); `kit.tsx` `Banner` (page call-out)
  is the only Banner left.
- **Two `LabelChip`s.** `sessions/sheets.tsx` (label colour enum) and
  `settings/pages/hostkit.tsx` (raw tint).
- **Two `SessionMenu`s.** `chat/SessionMenu.tsx` (conversation header) and
  `sessions/menus.tsx` (list row), same export name.
- **Two confirms.** `tools/Confirm.tsx` (`useConfirm`, a dialog) and `kit.tsx` `Confirm`
  (inline second press).
- **Two clipboard helpers.** `shell/copy(.web).ts` and `tools/clipboard(.web).ts` both export
  `copyText`.
- **Two `openSheet`/`closeSheet` pairs** (`sessions/directory.ts`, `hosts/state.ts`) and two
  `renameSession`s (`chat/actions.ts`, `sessions/directory.ts`); three "client or throw"
  helpers (`need()` in `sessions/directory.ts` and `hostkit.tsx`, `client()` in
  `chat/actions.ts`).
- **Hand-rolled primary button.** `SessionList` row's Approve/Review re-implements
  `Button kind="primary" kbd` with a different gradient (`#7fd9e6 → #25b5c8`, two stops)
  from `Button` (`#7fd9e6 → #25b5c8 55% → #045b9d`).
- **Badges** are styled twice (`Rail`, `PhoneTabs`) with an untokenised text colour `#1a1204`.
- **Text inputs** come in at least five styles: settings `NumField`/`TextField`, kit `Field`,
  settings `Area`, the session-list filter, the new-session prompt, the permission reply.
- **`Brackets`** is a primitive used by five files but lives in `SessionList.tsx`.
- **Status ordering** (`needs, failed, review, working, idle`) is declared in both
  `SessionList.tsx` and `Palette.tsx`.
- **Scrims:** `color.scrim` in the shell and new-session sheet, `rgba(0,0,0,0.5)` in the
  phone More sheet. Rail hover uses a literal `rgba(255,255,255,0.08)` rather than a wash token.

### Inconsistent motion

- **Two "standard" curves.** `tokens.ease` = `cubic-bezier(0.22,1,0.36,1)` is exported but
  unused; the Rail indicator and the Toggle knob repeat it as string literals. `anim()`'s
  default (enter, snap, toast, slash menu, tool rows) is `cubic-bezier(0.23,1,0.32,1)`.
- **One action, two timings.** A rail switch glides the indicator over 450ms while the side
  panel enters over 200ms on a different curve.
- **Toggle** animates its track over .25s with the default `ease` and its knob over .3s with
  the custom curve.
- **Transitions are literals** in component files (`Rail.tsx`, `settings/controls.tsx`), not
  tokens; keyframe animations go through `motion`.
- **Overlays agree (fixed).** Menu/Popover, wide Select, Dialog/Confirm, Palette and the desktop
  new-session overlay share `overlayMotion` + `usePresence` (components/presence.ts): 160-170ms
  fade + scale in on `ease`, 110ms out, mounted through exit; the narrow Select sheet slides up
  200ms. Still static: the phone More sheet and the portrait-tablet drawer; the phone
  new-session sheet keeps the native Modal slide.
- **Enter without exit.** Toasts, the slash menu and tool rows animate in but are removed
  instantly; the toast stack jumps when one leaves.
- **Instant state changes** where a transition would read better: Usage provider cards, the
  compaction summary, Tabs underline, Seg.
- **Native has no motion at all**: every animation is a web CSS keyframe or transition;
  `anim()` and `web()` return `{}` on native.
- **Reduced motion** clamps all animation to 1ms and one iteration, so the breathing
  working glyph and the shimmer stop entirely rather than going static by design.
- **Ligatures:** `Code.tsx` turns off font ligatures; Markdown's inline and fenced code does
  not, so `>=` renders as `≥` in replies.

### Components lacking states

- **No focus styles** on any text input (outline removed on web) and no visible focus on
  Button, Seg, Tabs or rows.
- **Button** has no pressed state and no loading indicator (callers swap the label).
- **Markdown** supports headings, bullets (numbered render as bullets), tables, images, fenced
  code, inline code, bold and italics; quotes, links and rules render as plain text.
- **Toasts** have no hover-to-pause; the 4200ms lifetime runs regardless.
- **Unhandled rejection:** `StatusBar` calls `void watchCheckout(cwd)` with no catch, so a
  failed `getCheckoutStatus` surfaces as an uncaught promise error (seen in the lab before the
  fixture host answered checkout reads). `watchTerminals` callers do catch.
- **Panels the fixture host can't populate** (Search, Files, PRs & CI, Tasks, Plugins,
  Companion, Terminals) show only their empty or unavailable states in the lab; showing them
  populated needs more fixture RPCs in `src/lab/client.ts`.

Daemon 1.6.11 advertises all real sources; none is gated above it. An older daemon (no `providerSubagents`) just
contributes no subagents: no RPC, no error. The version banner stays the only hint.

Opening an item (`openSubWork`): a child session opens as itself; a subagent whose id holds a claim on a loaded
to-do opens that to-do in Tasks; a terminal or script with a terminal opens in Terminals; anything else opens its
details in the parent's chat pane (`subwork-detail`), where a subagent's own timeline loads through
`agent.provider_subagents.timeline.get` and streams through the `timeline` updates. Selecting another session
closes the details.
Gaps for the daemon: a structured background-command/monitor track; script/terminal ownership by session
(they are workspace/cwd scoped, so every session in that workspace shows them); a way to stream subagent updates
for sessions the client is not viewing (rows fetch only for working or open sessions).
