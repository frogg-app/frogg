Several devices can be on the same agent or terminal at once — your laptop and your phone,
or two people paired to the same daemon. Frogg shows who they are rather than locking
anyone out.

## Who else is here

An agent chat carries a row pinned at the top inside its composer (a terminal, above its
output): a stack of avatars for the other devices on that session and one sentence about
them. Whoever is actively writing leads it ("Paz is typing…" with animated dots and a live
dot, then "2 more here"); otherwise it says who is there
("Paz and Sam are here").

<Screenshot src={appSessionPresenceImg} alt="Avatar stack above the composer with the line: Paz's laptop is typing, 1 more here" />

| Shown as | Meaning |
| -------- | ------- |
| is viewing / is here | The device has the session open |
| is typing | It edited its composer text in the last 5 seconds |
| is sending | The daemon saw it send a message to the agent |
| is typing here | The daemon saw it send keystrokes to the terminal |
| is idle | It is still there, but not doing anything |

Three avatars fit; the rest fold into a `+N`. Each person keeps the same avatar colour
everywhere. `viewing`, `typing` and `idle` are what the other device reports about itself;
`sending` and terminal input are what the daemon saw for itself.

The row disappears when nobody else is there, when the daemon does not support presence,
or when the presence request fails — it is chrome, and never makes a session look broken.
Devices re-report every 30 seconds and the daemon drops an entry it has not heard about
for 90 seconds, so someone who closes a laptop lid stops showing up on their own.

While someone else is writing to the same agent, the composer also takes a quiet accent
edge. It is a cue, not a block: the composer stays fully usable and both messages reach the
agent.

## Everyone connected to a host

**Host settings → Devices → Connected now** lists every client connected to that host right
now — paired devices and loopback or trusted-network connections alike — with the sessions
each one is in and when it connected. Every role can see it; it grants nothing.

<Screenshot src={appConnectedClientsImg} alt="Connected now: your name field, then one row per connected client with its avatar, badges and the session it is in" />

- **Your name** is how you appear to everyone else on the host. It defaults to the device
  name: the signed-in username on Windows and macOS desktops, the hostname on Linux, and
  the phone's name on mobile. It is stored on this device, and takes effect within one presence heartbeat —
  no reconnect. A paired device keeps the name on its credential, which an owner can
  rename under **Paired devices**.
- **Nicknames**: the pencil on another client's row gives it a nickname only you see. It
  replaces that client's own name in the presence row and in this list, follows that app
  across reconnects, and never leaves your device.

## Device names are not trusted

A device's name is chosen by that device. Frogg shows it as plain, truncated text and
never as part of its own chrome, so a name cannot dress itself up as an app message. The
same applies to the name on a pairing request waiting for approval.

Names come from the paired device's credential, or — for a connection that carries no
credential, such as loopback or a trusted LAN — from the name that client chose under
**Your name**. A client is never identified to others by its connection id; nicknames are
keyed by a one-way hash of the other app's install id.

## Requirements

Presence needs a daemon that advertises the `sessionPresence` feature; **Connected now**,
live renaming and nicknames need `connectedClients`. Against an older daemon those parts
simply do not appear. Nothing about presence
changes what a device may do: that is its
[role](/docs/self-hosting/security/#device-roles).
