Every daemon can serve the full app to a browser from its own **web client** server. There
is no hosted Frogg web app; you open your own host's address.

The web client has its own port, beside the daemon's. It serves only the app; the page then
connects to the daemon's port for everything it does.

| Channel     | Daemon | Web client |
| ----------- | ------ | ---------- |
| frogg       | `9999` | `9998`     |
| frogg beta  | `9989` | `9988`     |
| Dev build   | free   | free       |

## Turn it on

From another client (the desktop or mobile app), open the host's settings: **Web client**
starts and stops it, sets whether it starts with the daemon, and picks the interface it
listens on. While it runs, the card links to it. The browser app itself does not show the
card, so a page cannot switch off the server it came from.

The web client listens on `127.0.0.1` (this machine only) unless you pick another interface.
The card lists the host's interfaces: loopback, each network address, and `0.0.0.0` for all
of them. Choose a network address, or `0.0.0.0`, to open it from other devices.

Daemons installed with `install.sh`, Nix or `frogg install-service` start it with the daemon
by default; Docker also binds it to `0.0.0.0` inside the container and publishes port 9998.
For a daemon you start by hand, `frogg start --web-ui` starts it for that run.

Then open `http://<host>:9998/`.

### Configuration

| `config.json`                  | Environment              | Default          |
| ------------------------------ | ------------------------ | ---------------- |
| `features.webUi.enabled`       | `FROGG_WEB_UI_ENABLED`   | `false`          |
| `features.webUi.host`          | `FROGG_WEB_UI_HOST`      | `127.0.0.1`      |
| `features.webUi.port`          | `FROGG_WEB_UI_PORT`      | the brand's web port |

The app writes `features.webUi.enabled` and `features.webUi.host`. `FROGG_WEB_UI_ENABLED`
is only the default for `enabled`, so what you choose in the app holds across restarts;
`--web-ui` / `--no-web-ui` on `frogg start` fix it for that run and grey the switch out.

## Access

The page itself loads without credentials; everything it does goes through the normal
[access rules](/docs/getting-started/connect-and-pair/#who-can-connect):

- From loopback or a private network with LAN trust on, the app opens directly.
- From a public address, the browser sees a pairing page until the daemon is claimed or
  you pair.
- With a password set, the app asks for it.

The daemon speaks plain HTTP. For HTTPS, put a reverse proxy in front of it and add its
hostname to `daemon.hostnames`; see [security](/docs/self-hosting/security/#tls-and-reverse-proxies).

## Differences from the desktop app

- No **Remote SSH** connections or SSH deploy.
- No QR scanning; use **Paste pairing link**.
- The browser connects to other daemons only if they allow the origin
  (`daemon.cors.allowedOrigins`).

## Serve a different build

`features.webUi.distDir` (or `FROGG_WEB_UI_DIST_DIR`) serves another web export, for example
one you built with `npm run build:ui`.
