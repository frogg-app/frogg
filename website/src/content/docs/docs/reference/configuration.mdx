The daemon reads `$FROGG_HOME/config.json`. `FROGG_HOME` defaults to `~/.frogg`. A custom brand
uses its own home and variable, for example `~/.acme` and `ACME_HOME`. In a branded deployment,
use that brand's prefix for every environment override; inherited `FROGG_*` values are ignored.

## Basics

- The file is created on first start with the defaults below, with private permissions.
- The schema is **strict**: unknown keys fail startup with
  `[Config] Invalid config in <path>`. Only `daemon.mcp` and `daemon.browserTools` accept
  extra keys. A top-level `listen` is an unknown key: the listen address is
  `daemon.listen`. A key added in a newer release fails startup on an older daemon, so
  write it only after the new version is installed, and remove it before rolling back.
  See [provisioning](/docs/self-hosting/provisioning/).
- Environment variables and CLI flags override the file. See
  [environment variables](/docs/reference/environment-variables/).
- Apply changes with `frogg reload`. It reports which paths applied live, which need
  `frogg restart`, and which are pinned by an env var or flag.
- `frogg config-format` rewrites the file with consistent formatting and keeps your values.
- The app's host settings edit the same file.

## Default file

This is exactly what a new daemon writes (0.6.19):

```json title="~/.frogg/config.json"
{
  "version": 1,
  "daemon": {
    "mcp": { "enabled": true, "injectIntoAgents": false },
    "browserTools": { "enabled": false },
    "git": { "maxProcessesPerSecond": 2048, "maxProcessConcurrency": 8 },
    "autoArchiveAfterMerge": false,
    "autoResumeOnUsageLimit": true,
    "autoUpdate": { "enabled": false, "channel": "stable", "checkIntervalHours": 24, "quietHours": null },
    "enableTerminalAgentHooks": false,
    "appendSystemPrompt": "",
    "cors": { "allowedOrigins": [] },
    "relay": { "enabled": false }
  },
  "app": { "pairingBaseUrl": "https://pair.frogg.app" },
  "log": { "level": "info", "format": "json" }
}
```

## `daemon`

### Listening and access

| Key                     | Type                    | Default          | Meaning |
| ----------------------- | ----------------------- | ---------------- | ------- |
| `daemon.listen`         | string                  | unset            | Listen target. Forms: `host:port`, `9999`, `:9999`, `[::1]:9999`, a Unix socket path (`/run/frogg.sock`, `~/frogg.sock`, `unix://...`) or a Windows pipe (`\\.\pipe\frogg`, `pipe://frogg`). A new daemon does not write this key: with it unset the bind host comes from the brand (`0.0.0.0` for `frogg`, `127.0.0.1` for a brand asking for a loopback bind) on port `$PORT` or `9999`. Precedence: `--listen` > `FROGG_LISTEN` > this key > the brand bind |
| `daemon.hostnames`      | `true` or string[]      | unset            | Allowed `Host` headers (DNS-rebinding protection). `localhost`, `*.localhost`, IP addresses and the pairing host are always allowed. A leading `.` matches subdomains. `true` allows any host |
| `daemon.allowedHosts`   | same                    | unset            | Legacy alias of `hostnames` |
| `daemon.allowPairingHostname` | boolean           | `true`           | Accept the pairing host (`pair.frogg.app`) as a `Host` without listing it. Useful only if you reverse-proxy that name at this daemon; set `false` if you do not |
| `daemon.trustedProxies` | `true` or string[]      | `["loopback"]`   | Proxies whose `X-Forwarded-For` is trusted. Entries are IPs or `"loopback"` |
| `daemon.cors.allowedOrigins` | string[]           | `[]`             | Extra browser origins. `"*"` allows any. The daemon's own origins and the desktop app origin are always allowed |
| `daemon.auth.password`  | scrypt hash             | unset            | Require a password from every client. Set it with `frogg auth set-password`; do not write it by hand. Legacy bcrypt hashes still verify |
| `daemon.auth.trustLan`  | boolean                 | brand default (`true` for `frogg`, else `false`) | Treat private-network clients like loopback (no credential needed) when no password is set. Ignored while `claimMode` is on |
| `daemon.auth.claimMode` | boolean                 | brand default (`false` for `frogg`) | Lock the LAN out: every client needs a credential, and the first client to reach an unclaimed daemon claims it as owner. Turning it off hands the LAN back to `trustLan`, so set `trustLan: false` with it on untrusted networks |
| `daemon.auth.claimScope` | `"any"` or `"local"`  | brand default (`"any"`) | Who may claim an unclaimed daemon in claim mode. `"local"` accepts only a loopback client whose bearer is the daemon's local token; anyone else gets `403`. Read at startup. Not read by 1.5.34 and earlier, which refuse a file containing it |
| `daemon.security.acknowledgedFindings` | string[] | unset | Warning finding ids an owner marked as intended in the app (host settings, **Security**); they raise no notification dot. Written by the app; critical findings are never suppressed. Not read by 1.5.35 and earlier, which refuse a file containing it |

See [security and access](/docs/self-hosting/security/) for how these combine.

### Agents and tools

| Key                               | Type    | Default | Meaning |
| --------------------------------- | ------- | ------- | ------- |
| `daemon.mcp.enabled`              | boolean | `true`  | Serve the agent MCP endpoint at `/mcp/agents` |
| `daemon.mcp.injectIntoAgents`     | boolean | `false` | Give agents the daemon's `frogg` MCP server automatically |
| `daemon.browserTools.enabled`     | boolean | `false` | Expose browser automation tools over MCP |
| `daemon.appendSystemPrompt`       | string  | `""`    | Text appended to every agent's system prompt |
| `daemon.autoArchiveAfterMerge`    | boolean | `false` | Archive agents after their branch merges |
| `daemon.autoResumeOnUsageLimit`   | boolean | `true`  | When a session hits its provider usage limit, send a resume prompt a minute after the limit resets. The composer shows a countdown that cancels it |
| `daemon.hostSettings.hiddenSections` | string[] | brand default | Host settings sections the app does not offer for this daemon: any of `projects`, `pair-device`, `devices`, `agents`, `providers`, `terminals`, `host`. `usage` is still accepted but ignored: usage now lives under Providers. **Security** cannot be hidden |
| `daemon.enableTerminalAgentHooks` | boolean | `false` | Install activity hooks for agent CLIs started in terminals |
| `daemon.terminalProfiles`         | array   | built-in profiles | `[{ id, name, command, args?, icon? }]`. `[]` means none |
| `daemon.agentProfiles`            | array   | unset   | Saved agent presets: `[{ id, name, provider, model?, modeId?, thinkingOptionId?, featureValues?, notes?, icon?, color? }]` |
| `daemon.git.maxProcessesPerSecond` | integer | `2048` | Git process spawn rate limit |
| `daemon.git.maxProcessConcurrency` | integer | `8`    | Concurrent git processes |

### Updates

| Key                                  | Type                    | Default    | Meaning |
| ------------------------------------ | ----------------------- | ---------- | ------- |
| `daemon.autoUpdate.enabled`          | boolean                 | `false`    | Let the daemon update itself |
| `daemon.autoUpdate.channel`          | `stable` or `beta`      | `stable`   | Release channel |
| `daemon.autoUpdate.checkIntervalHours` | number                | `24`       | Hours between checks. The first check is 5 minutes after start |
| `daemon.autoUpdate.quietHours`       | `[start, end]` or null  | `null`     | Local hours (0-23) when updates wait. The window may wrap midnight |

The auto-updater defers by 15 minutes while agents are running or during quiet hours.
It only works for installs made with `install.sh`. See [updates](/docs/self-hosting/updates/).

### Relay

| Key                          | Type    | Default          | Meaning |
| ---------------------------- | ------- | ---------------- | ------- |
| `daemon.relay.enabled`       | boolean | `false`          | Connect to a relay. Without an endpoint the daemon still starts, logs a warning and runs no relay |
| `daemon.relay.endpoint`      | string  | unset            | `host:port` of your relay. Also settable in the app under host settings, **Pair devices** |
| `daemon.relay.publicEndpoint` | string | `endpoint`       | Endpoint advertised to clients |
| `daemon.relay.useTls`        | boolean | `true`           | TLS to the relay. Set `false` only for a plaintext test relay |
| `daemon.relay.publicUseTls`  | boolean | `useTls`         | TLS advertised to clients |

Frogg does not operate a public relay, and no brand ships a relay endpoint. Deploy
`packages/relay` yourself to use one.

The endpoint comes from `FROGG_RELAY_ENDPOINT`, then `daemon.relay.endpoint`. Setting it
in the app writes `daemon.relay.endpoint` and `daemon.relay.useTls` and applies them
without a restart. While `FROGG_RELAY_ENDPOINT`, `FROGG_RELAY_USE_TLS` or a relay TLS CLI flag
is set, the app shows the endpoint read-only.

### Service proxy

| Key                                  | Type    | Meaning |
| ------------------------------------ | ------- | ------- |
| `daemon.serviceProxy.listen`         | string  | Separate listener for workspace service URLs |
| `daemon.serviceProxy.publicBaseUrl`  | URL     | Public base for service links, e.g. `https://dev.example.com` |
| `daemon.serviceProxy.enabled`        | boolean | Compatibility key only; slated for removal |

### Workspace services

| Key                                  | Type   | Default     | Meaning |
| ------------------------------------ | ------ | ----------- | ------- |
| `daemon.workspaceServices.bindHost`  | string | `127.0.0.1` | The `HOST` workspace dev servers bind to |

A workspace service (a `frogg.json` script declared as a service) binds to loopback by
default, **even when the daemon itself listens on `0.0.0.0`**. Reach it from another device
through the daemon's service proxy, which authenticates the request, rather than by
connecting to the dev server's port directly.

Setting the key to `0.0.0.0` puts dev servers back on every interface. They have no
authentication of their own, so anything that can reach the port can reach the service.

The default comes from the brand's `daemon.workspaceServicesBind`, and
`FROGG_WORKSPACE_SERVICES_BIND_HOST` overrides both. Changing it takes effect for services
started after the daemon restarts.

## `providerUpdates`

How the daemon keeps provider CLIs current. See
[keeping providers up to date](/docs/agents-and-providers/providers/#keeping-providers-up-to-date).

| Key                                   | Type     | Default | Meaning |
| ------------------------------------- | -------- | ------- | ------- |
| `providerUpdates.checkEnabled`        | boolean  | brand default (`true`) | Poll for newer provider releases in the background. Providers not installed on the host are skipped |
| `providerUpdates.autoUpdate`          | boolean  | `false` | Install newer releases as they are found, without asking |
| `providerUpdates.checkIntervalMinutes`| integer  | `720`   | Minutes between background checks |
| `providerUpdates.ignoredProviders`    | string[] | `[]`    | Provider ids excluded from checking and automatic installs |

```json
{
  "providerUpdates": {
    "autoUpdate": true,
    "checkIntervalMinutes": 360,
    "ignoredProviders": ["omp"]
  }
}
```

## `providerAccounts`

Multi-sign-in state, keyed by provider id. `claude` and `codex` support accounts today; the
other entries exist so enabling one is a config edit. See
[provider accounts](/docs/agents-and-providers/providers/#provider-accounts-multi-sign-in).

`providerAccounts.gemini.enabled` is a special case. Gemini CLI has no config-directory
environment variable, so each Gemini account runs the CLI with the account directory as its
`HOME`; only a fixed set of entries (`.npm`, `.npmrc`, `.cache`, `.gitconfig`, `.ssh`,
`.config/gcloud`) is symlinked back to your real home, and anything else Gemini reads from
home will be missing. See
[Gemini: accounts through a per-account HOME](/docs/agents-and-providers/providers/#gemini-accounts-through-a-per-account-home)
before enabling it.

| Key                                      | Type             | Default              | Meaning |
| ---------------------------------------- | ---------------- | -------------------- | ------- |
| `providerAccounts.<provider>.enabled`    | boolean          | `true` for `claude` and `codex`, `false` otherwise | Whether the daemon accepts account management for the provider |
| `providerAccounts.<provider>.activeAccountId` | string \| null | unset                | Account whose config directory the provider's agents use |
| `providerAccounts.<provider>.accounts`   | array            | `[]`                 | Managed accounts; written by the daemon, not hand-edited |
| `providerAccounts.<provider>.accounts[].allowedModels` | string[] | unset | Model ids this account may run. Unset means every model the provider offers; `[]` permits none |

```json
{
  "providerAccounts": {
    "claude": {
      "enabled": true,
      "activeAccountId": "4d1c…",
      "accounts": [
        {
          "id": "4d1c…",
          "provider": "claude",
          "name": "peter",
          "configDir": "/home/frogg/.claude-peter",
          "linkedFolders": ["commands", "skills", "agents", "projects", "sessions", "shell-snapshots"],
          "createdAt": "2026-09-17T09:00:00.000Z",
          "allowedModels": ["claude-opus-4-6", "claude-sonnet-4-5"]
        }
      ]
    }
  }
}
```

## Reload behaviour

`frogg reload` applies these without a restart: `daemon.relay.enabled`,
`daemon.relay.endpoint`, `daemon.relay.useTls`, `daemon.mcp.*`,
`daemon.browserTools.enabled`, `daemon.hostnames`, `daemon.cors.allowedOrigins`,
`daemon.trustedProxies`, `daemon.auth.trustLan`, `daemon.auth.claimMode`, `daemon.git.*`,
`daemon.autoArchiveAfterMerge`, `daemon.autoResumeOnUsageLimit`, `daemon.hostSettings.hiddenSections`, `daemon.autoUpdate`, `daemon.enableTerminalAgentHooks`,
`daemon.appendSystemPrompt`, `daemon.terminalProfiles`, `daemon.agentProfiles`,
`app.pairingBaseUrl` and `agents.*`.

Everything else, including `daemon.listen`, `daemon.auth.password`, `features`
and `log`, needs `frogg restart`.
